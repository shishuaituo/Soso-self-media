# 第三阶段：Skill 架构设计

## 一、Skill 基本信息

### 名称与定位
- **Skill 名称**：`self-media-lab`（自媒体实验室）
- **触发描述**：自媒体运营全流程助手，支持选题挖掘、对标账号分析、爆款结构拆解和内容初稿生成。当用户需要做自媒体选题、分析对标账号、拆解爆款内容或生成内容初稿时调用。
- **核心能力**：基于 Firefly 社媒数据 API，提供抖音/小红书/视频号/公众号的内容数据，结合 AI 分析能力，完成从选题到初稿的全流程辅助。

### 设计原则
1. **模块化**：四大模块可独立使用，也可串联工作流
2. **平台无关**：统一抽象层，适配多平台（抖音/小红书/视频号/公众号）
3. **成本意识**：智能选择接口，优先低成本接口，提示积分消耗
4. **错误友好**：优雅处理 API 错误，给出明确指引
5. **增量配置**：用户配置逐步积累，不需要一次性填完

## 三、四大业务模块设计

### 模块1：选题挖掘 (topic-mining)

**功能**：根据用户指定的领域/关键词，搜索平台热门内容，分析并生成候选选题清单。

#### 输入
- 必填：关键词 / 领域（如 "AI 工具"、"职场成长"）
- 可选：
  - 目标平台（默认抖音，可选小红书/视频号）
  - 时间范围（默认最近一周）
  - 排序方式（默认最多点赞）
  - 选题数量（默认 10 个）
  - 内容类型（视频/图文/不限）

#### 工作流
```
1. 接收关键词和筛选条件
   ↓
2. 调用搜索接口（video_search / note_search）
   ├─ sort_type = 最多点赞
   ├─ publish_time = 最近一周
   └─ 取前 20 条
   ↓
3. 数据清洗与分析
   ├─ 提取标题、描述、话题标签
   ├─ 统计高频关键词
   ├─ 按选题方向聚类
   └─ 评估热度和竞争度
   ↓
4. 生成候选选题清单
   ├─ 选题方向
   ├─ 热度评分
   ├─ 参考案例（2-3 个）
   └─ 创作建议
```

#### 输出格式
```
📊 选题挖掘报告
━━━━━━━━━━━━━━━━
关键词：AI 工具
平台：抖音
时间范围：最近一周
本次消耗：13 积分

🔥 热门选题方向 TOP 10
━━━━━━━━━━━━━━━━
1. AI 工具效率提升（热度：⭐⭐⭐⭐⭐）
   参考案例：
   - 「3个AI工具让效率翻倍」12.5w赞
   - 「打工人必备AI神器」8.3w赞
   创作建议：从具体场景切入，展示前后对比

2. ...

- 干货类内容互动率较高

- 抖音：13 积分/次
- 小红书：13 积分/次

### 模块2：对标账号分析 (account-analysis)

**功能**：输入对标账号链接或 ID，深度分析账号策略、内容规律和数据表现，生成拆解报告。

#### 输入
- 必填：账号链接 或 sec_user_id / user_id
- 可选：
  - 分析深度（基础版/完整版，默认基础版）
  - 作品分析数量（默认 30 条）

#### 工作流
```
1. 接收账号标识（链接/ID）
   ↓
2. 调用账号信息接口（user_info）
   └─ 获取基础数据（粉丝、获赞、简介等）
   ↓
3. 调用账号作品接口（user_videos / user_notes）
   └─ 获取作品列表（按分析深度决定数量）
   ↓
4. 深度分析
   ├─ 账号定位与人设分析
   ├─ 内容主题分类与占比
   ├─ 发布频率与时间规律
   ├─ 爆款作品筛选与特征
   ├─ 互动数据统计（均值/分布）
   ├─ 标题风格分析
   └─ 标签使用策略
   ↓
5. 生成账号拆解报告
```

#### 输出格式
```

━━━━━━━━━━━━━━━━

### 模块3：爆款结构拆解 (viral-deconstruction)

**功能**：输入多个爆款内容链接，拆解其结构、钩子、节奏和亮点，提炼可复用模板。

#### 输入
- 必填：3-5 个爆款内容链接
- 可选：
  - 拆解维度（全维度/指定维度）
  - 输出模板类型

#### 工作流
```
1. 接收爆款链接列表
   ↓
2. 批量调用详情接口（video_detail / note_detail）
   └─ 获取每条内容的完整信息
   ↓
3. 批量调用评论接口（可选，用于分析用户反馈）
   └─ 获取热门评论
   ↓
4. 多维度拆解分析
   ├─ 选题方向分析（高频选题提取）
   ├─ 开头钩子分析（前3秒/前30字）
   │  ├─ 钩子类型归类
   │  └─ 效果对比
   ├─ 内容结构拆解（起承转合）
   │  ├─ 段落划分
   │  ├─ 节奏分析
   │  └─ 信息密度
   ├─ 金句/亮点提取
   ├─ 评论区热点提取
   └─ 结尾引导分析
   ↓
5. 提炼可复用模板
   ├─ 结构模板
   ├─ 钩子模板
   └─ 选题模板
```

#### 输出格式
```

## 四、配置管理设计

### 用户配置项（逐步积累）

| 配置项 | 说明 | 何时需要 |
|--------|------|----------|
| `api_key` | Firefly API Key | 首次使用前 |
| `default_platform` | 默认使用的平台 | 首次使用时询问 |
| `persona` | 人设信息（背景、风格、经历等） | 生成初稿时 |
| `target_audience` | 目标受众画像 | 生成初稿时优化 |
| `content_style` | 内容风格偏好 | 生成初稿时 |
| `common_topics` | 常用领域/赛道 | 选题挖掘时默认关键词 |
| `competitor_accounts` | 关注的对标账号列表 | 快捷分析对标 |

### 配置存储方式
- 存储在对话上下文中（用户告知后记忆）
- Skill 文档中指导用户如何配置
- 每次使用前检查必要配置，缺失则引导用户提供

## 五、API 封装层设计

### 统一调用方式
- 使用 Python + urllib 发送 HTTP 请求
- 统一的错误处理和重试逻辑
- 自动生成幂等键（request_id）
- 积分消耗统计和提示

### 核心函数设计

```
firefly_api(platform, capability, params)
  ├─ 构造请求 URL
  ├─ 添加 API Key 头
  ├─ 生成幂等键
  ├─ 发送请求
  ├─ 处理响应
  ├─ 记录积分消耗
  └─ 返回 data 部分
```

### 错误处理策略
| 错误码 | 处理方式 |
|--------|---------|
| 1401 密钥无效 | 提示用户检查 API Key |
| 1402 积分不足 | 提示余额不足，引导充值 |
| 1429 请求频繁 | 自动等待后重试（最多2次） |
| 2404 内容不存在 | 提示内容链接无效或未收录 |
| 1502/1503/1504 上游问题 | 提示稍后再试，或建议换个内容 |

### 幂等键生成规则
- 格式：`{skill_name}_{module}_{timestamp}_{random}`
- 示例：`self_media_lab_topic_1724342400_a1b2c3`
- 同一参数重试使用相同 request_id，避免重复扣费

## 六、平台适配层设计

### 平台能力矩阵

| 能力 | 抖音 | 小红书 | 视频号 | 公众号 |
|------|------|--------|--------|--------|
| 内容搜索 | ✅ | ✅ | ✅ | ❌ |
| 内容详情 | ✅ | ✅ | ✅ | ✅ |
| 评论 | ✅(2分) | ✅(13分) | ✅(13分) | ✅(13分) |
| 账号信息 | ✅(2分) | ✅(13分) | ✅(13分) | ✅(13分) |
| 账号作品 | ✅(2分) | ✅(13分) | ✅(13分) | ✅(13分) |
| 分享链接解析 | ✅ | ✅ | ✅ | - |

### 统一参数映射
- 统一的 `search(keyword, options)` 接口
- 统一的 `get_content(url_or_id)` 接口
- 统一的 `get_account(url_or_id)` 接口
- 统一的 `get_account_content(url_or_id)` 接口
- 统一的 `get_comments(content_id)` 接口

各平台参数差异在适配层内部处理，上层模块只调用统一接口。

### 输出格式规范（必读）

> **重要规则**：所有展示给用户的结果中，每一条视频/笔记都必须包含可点击的原始链接，方便用户直接跳转查看。

**链接生成规则**：
- 抖音视频：`https://www.douyin.com/video/{aweme_id}`
- 小红书笔记：`https://www.xiaohongshu.com/explore/{note_id}`

**API 返回数据要求**：
- 所有搜索/详情/账号作品接口的返回结果中，必须包含 `share_url` 字段
- 在 Exec 模板的 `.map()` 提取逻辑中内置 `share_url` 生成

**结果展示格式要求**：

1. **表格格式**（排行榜、对比）：

| 排名 | 标题 | 作者 | 点赞 | 链接 |
|------|------|------|------|------|
| 1 | 全屋定制5大避坑 | 锐哥 | 7.4w | [点击观看](https://www.douyin.com/video/xxx) |

2. **卡片格式**（重点展示）：

```
**【板材避坑】全屋定制！该怎么偷工减料？**
- 作者：旭东聊装修 | 点赞：18.3w | 评论：1.3w
- 链接：[点击观看视频](https://www.douyin.com/video/xxx)
```

3. **列表格式**（选题清单）：

```
1. **全屋定制5大避坑指南** — 锐哥聊装修 7.4w赞
   👉 [点击观看](https://www.douyin.com/video/xxx)
```

**规则**：无论是选题挖掘、对标分析还是爆款拆解的输出，每一条内容都必须附带原始链接。链接文字统一用「点击观看」（抖音视频）或「点击查看」（小红书笔记）。

## 七、触发与使用方式

### 触发场景
1. 用户明确说"帮我找选题"、"分析这个账号"、"拆解爆款"、"写个脚本"等
2. 用户发送抖音/小红书链接，要求分析
3. 用户提到自媒体运营相关的需求

### 交互模式
- **单模块调用**：用户只需要某一个功能
- **串联工作流**：用户说"帮我做一套自媒体方案"，按顺序走完全流程
- **渐进式**：先找选题，选一个后再拆解，再生成初稿

### 使用流程示例
```
用户："帮我分析一下这个抖音账号 [链接]"
  ↓
Skill：识别为对标分析需求
  ↓
